```
[WAV Source 48kHz] -> [PCM Packetizer] -> [Conv FEC K=7 R=1/2] -> [QPSK Gray-mapped] -> [Tx RRC]
```

### 3.1 Task MCOM-03: Digital Modem Transceiver and Synchronization (GATE-3)

```markdown
TECHNICAL SPECIFICATION: MCOM-03
MILESTONE: GATE-3 (Digital Modem & Timing Recovery)
TARGET DEADLINE: 2026-11-24

1. TECHNICAL OBJECTIVE:
Construct the end-to-end digital RF physical layer in GNU Radio 3.10.12.0, connecting the packetized audio byte stream from GATE-2 to a coherent QPSK transceiver with pulse shaping, timing recovery, carrier synchronization, and forward error correction.

2. INPUT INTERFACE:
- Source: Byte stream generated by `PCMPacketizerBlock` in `pcm_framing.py` (packet length: 104 bytes, 48-sample audio payload @ 48 kHz).

3. DSP CHAIN & GNU RADIO 3.10 BLOCK SPECIFICATIONS:
- Forward Error Correction (Encoder): Convolutional encoder via `fec.cc_encoder_make(frame_size, K=7, rate=2, polys=[0o171, 0o133], start_state=0)`.
- Symbol Mapping: QPSK Gray-mapped constellation via `digital.constellation_qpsk()`.
- Pulse Shaping (Transmitter): Root Raised Cosine (RRC) filter with samples per symbol SPS = 4, excess bandwidth alpha = 0.35, filter length = 11 * SPS.
- Channel Model (AWGN Baseline): `channels.channel_model` with adjustable noise voltage for SNR sweeps.
- Matched Filtering (Receiver): Identical Root Raised Cosine (RRC) matched filter with SPS = 4, alpha = 0.35.
- Symbol Timing Recovery: `digital.symbol_sync_cc` using Gardner timing error detector (`digital.TED_GARDNER`), damping factor = 1.0, loop bandwidth = 2 * pi / 100, interpolator = `digital.IR_MMSE_8TAP`. (Do not use obsolete blocks such as `pfb_clock_sync_ccf`).
- Carrier Frequency & Phase Synchronization: `digital.costas_loop_cc(loop_bw=2*pi/100, order=4, use_snr=False)`. Must be placed after symbol timing recovery.
- Channel Decoding: Soft or hard-decision Viterbi decoder via `fec.cc_decoder_make`.
- Output Interface: Recovered byte stream fed directly into `PCMDepacketizerBlock` in `pcm_framing.py`.

4. DELIVERABLES:
- Flowgraph source: `rf_qpsk_link.grc`.
- Compiled Python script: `rf_qpsk_link.py` (generated via `grcc.exe rf_qpsk_link.grc`).

5. EXECUTION & VERIFICATION CONSTRAINTS:
- Execution environment: `C:\ProgramData\radioconda\python.exe`.
- Verification criteria: Symbol timing error detector and Costas loop must achieve phase and frequency lock on AWGN channel with Eb/N0 >= 8 dB.
```

### 3.3 Task MCOM-05: Dual-Branch Rayleigh Fading Channel and Custom MRC Python Block (GATE-4)

```markdown
TECHNICAL SPECIFICATION: MCOM-05
MILESTONE: GATE-4 (Multipath Fading & Diversity Combining)
TARGET DEADLINE: 2026-30-11

1. TECHNICAL OBJECTIVE:
Implement a 2-branch independent Rayleigh fading propagation channel with realistic Doppler spreading, and construct a custom GNU Radio Python Sync Block implementing Maximal Ratio Combining (MRC).

2. CHANNEL SPECIFICATIONS:
- Fading Channel Model: Two independent instances of `channels.fading_model`.
- Normalized Doppler Frequency: $f_D T_s = 1.0 \times 10^{-3}$, derived from:
  $$f_D = \frac{v}{\lambda} = \frac{v \cdot f_c}{c} = \frac{1.5 \cdot 2.4 \times 10^9}{3.0 \times 10^8} = 12.0\text{ Hz}$$
  $$T_s = \frac{SPS}{f_{\text{s,RF}}} = \frac{4}{48 \times 10^3 \times 16 / 2} \implies f_D T_s \approx 1.0 \times 10^{-3}$$
- Number of Rician/Rayleigh Sinusoids: 8 to 16 scatterers per branch.
- Underlying distribution: Zero Line-of-Sight component (K-factor = 0, pure Rayleigh).

3. CUSTOM MRC PYTHON BLOCK SPECIFICATION:
- Implementation class: `gr.sync_block` in `mrc_diversity_block.py`.
- Inputs: Branch 1 signal $r_1[n]$ (complex64), Branch 2 signal $r_2[n]$ (complex64), Branch 1 channel estimate $h_1[n]$ (complex64), Branch 2 channel estimate $h_2[n]$ (complex64).
- Combining Equation:
  $$y[n] = h_1^*[n] r_1[n] + h_2^*[n] r_2[n]$$
- Output: Combined complex symbol stream $y[n]$ (complex64).

4. DELIVERABLES:
- Custom Python Block: `mrc_diversity_block.py`.
- GNU Radio flowgraph: `diversity_rayleigh_link.grc` and compiled `diversity_rayleigh_link.py`.

5. EXECUTION CONSTRAINTS:
- Execution environment: `C:\ProgramData\radioconda\python.exe`.
- Block integration: The combined output $y[n]$ must directly feed the timing recovery and carrier recovery stages.
```

### 3.4 Task MCOM-06: Multi-Doppler Benchmarking and Diversity Gain Validation (GATE-4)

```markdown
TECHNICAL SPECIFICATION: MCOM-06
MILESTONE: GATE-4 (Scientific Diversity Benchmarking)
TARGET DEADLINE: 2026-30-11

1. TECHNICAL OBJECTIVE:
Conduct empirical parameter sweeps over the 2-branch Rayleigh fading channel across three Doppler velocity regimes, measuring bit error rates to prove diversity order L = 2 and quantifying diversity gain against single-branch reception.

2. MEASUREMENT MATRIX & TEST SCENARIOS:
- Doppler Velocity Regimes:
  * Static / Pedestrian Slow: $v = 0.15\text{ m/s}$ ($f_D = 1.2\text{ Hz}$, $f_D T_s = 1.0 \times 10^{-4}$).
  * Walking Musician on Stage: $v = 1.5\text{ m/s}$ ($f_D = 12.0\text{ Hz}$, $f_D T_s = 1.0 \times 10^{-3}$).
  * Vehicular / Extreme Movement: $v = 15.0\text{ m/s}$ ($f_D = 120.0\text{ Hz}$, $f_D T_s = 1.0 \times 10^{-2}$).
- Average SNR Sweep: Swept from $\bar{\gamma} = 0\text{ dB}$ to $30\text{ dB}$.

3. THEORETICAL BENCHMARK EQUATIONS:
- Single-Branch Rayleigh ($L = 1$):
  $$P_{b,1} \approx \frac{1}{4 \bar{\gamma}}$$
- Dual-Branch Maximal Ratio Combining ($L = 2$):
  $$P_{b,2} = \left[\frac{1}{2}\left(1 - \mu\right)\right]^2 (2 + \mu), \quad \text{where } \mu = \sqrt{\frac{\bar{\gamma}}{1 + \bar{\gamma}}}$$
  $$\text{At high SNR: } P_{b,2} \approx 3 \left(\frac{1}{4 \bar{\gamma}}\right)^2 \propto \bar{\gamma}^{-2}$$

4. DELIVERABLES:
- Automated sweep script: `fading_benchmark.py` (headless execution).
- Publication-quality comparative plots: `rayleigh_mrc_doppler_comparison.png` and `.pdf` showing:
  1. AWGN theoretical curve.
  2. Single-branch Rayleigh (empirical vs theory).
  3. Dual-branch MRC (empirical vs theory).
  4. Curves for all three Doppler velocity profiles.

5. ACCEPTANCE CRITERIA:
- The measured BER curve for 2-branch MRC must demonstrate a slope proportional to $\bar{\gamma}^{-2}$ (diversity order 2).
- Measured Diversity Gain at $BER = 10^{-3}$ must exceed $3.0\text{ dB}$.
```

### 3.5 Task MCOM-07: Multipath Equalization (LMS) and Algorithmic Latency Budget (GATE-5)

```markdown
TECHNICAL SPECIFICATION: MCOM-07
MILESTONE: GATE-5 (Adaptive Equalization & Latency Verification)
TARGET DEADLINE: 2026-12-05

1. TECHNICAL OBJECTIVE:
Integrate a decision-directed Least Mean Squares (LMS) linear equalizer to eliminate Inter-Symbol Interference (ISI) caused by multipath delay spread, and verify that total simulation-domain algorithmic latency satisfies $T_{\text{alg}} \le 5.0\text{ ms}$.

2. MULTIPATH DELAY SPREAD CHANNEL CONFIGURATION:
- Profile: Frequency-selective 2-ray or 3-ray multipath channel inducing delay spread $> 0.5 T_s$.
- Primary path: Direct LoS/scattered path (delay 0, gain 1.0).
- Secondary path: Delayed reflected path (delay $\tau = 1.5 T_s$, gain $\alpha = 0.5 e^{j \pi / 4}$).

3. ADAPTIVE EQUALIZER SPECIFICATION:
- Implementation Block: `digital.linear_equalizer(num_taps=15, sps=1, alg=digital.adaptive_algorithm_lms(cons, mu=0.001))`. (Do not use obsolete `lms_dd_equalizer_cc`).
- Adaptation Algorithm:
  $$w[n+1] = w[n] + \mu e^*[n] x[n]$$
  where $e[n] = d[n] - y[n]$ is the decision error relative to the QPSK constellation grid.

4. ALGORITHMIC LATENCY BUDGET AUDIT:
- KPI Scope: Simulation-domain algorithmic delay, strictly excluding OS soundcard driver buffers (WASAPI/PortAudio).
- Latency Breakdown Specification:
  * Framing delay ($T_{\text{framing}}$): 48 samples / 48 kHz = 1.000 ms.
  * RRC filter group delay ($T_{\text{RRC}}$): $2 \times 8 \times T_s = 16 \times (1 / 250\text{ kSym/s}) = 0.064\text{ ms}$.
  * FEC constraint length delay ($T_{\text{FEC}}$): $5 \times K \times T_s \approx 0.140\text{ ms}$.
  * Equalizer tap delay ($T_{\text{EQ}}$): $15 \times T_s \approx 0.060\text{ ms}$.
  * Processing / buffer margin ($T_{\text{margin}}$): $\approx 2.136\text{ ms}$.
  * Total Algorithmic Latency: $T_{\text{alg}} \approx 3.400\text{ ms} \le 5.000\text{ ms}$.

5. DELIVERABLES:
- Flowgraph: `iem_transceiver_complete.grc` and compiled Python script.
- Latency audit script: `measure_latency.py` (utilizing stream tag offsets or impulse injection).
- Tabular latency budget report for the final thesis.
```

## 4. Documentation and Markdown Conventions

To maintain consistency across workspaces and Obsidian knowledge bases, all project documentation must adhere to the following rules:

1. **Zero Icons and Emojis**:
   - Do not use emoji symbols or decorative icons in headings, bullet points, table headers, or text bodies.
   - Use standard alphanumeric characters, descriptive keywords, and standard mathematical notation.
2. **Standard CommonMark and Obsidian Headings**:
   - Use clean markdown headings: `#`, `##`, `###`, `####`.
   - Keep titles informative, concise, and structured.
3. **Obsidian-Compatible Callouts**:
   - Use standard GitHub / Obsidian callout syntax for emphasized notes:
     ```markdown
     > [!info]
     > Informational note text.

     > [!warning]
     > Warning or environment constraint.

     > [!note]
     > Technical observation.
     ```
   - Do not place decorative icons inside callout headers or text.
4. **Mathematical Expressions**:
   - Inline math must be formatted using LaTeX `$ ... $` syntax (e.g., $f_D T_s = 1.0 \times 10^{-3}$).
   - Standalone display equations must be formatted using `$$ ... $$` on dedicated lines.
5. **Zero Personal Data**:
   - Never record personal exam dates, re-exam schedules, student IDs, or private calendars in team-shared documents.
